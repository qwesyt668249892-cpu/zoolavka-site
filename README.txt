ZOOLAVKA — ПАПКА ДЛЯ САЙТА (GitHub Pages)
=============================================

ЧТО ВНУТРИ
----------
index.html      — сама страница сайта
styles.css      — все стили
script.js       — вся логика (каталог, корзина, оформление заказа)
images/         — все картинки товаров, логотип и бегающая собачка
robots.txt      — разрешает поисковикам индексировать сайт
sitemap.xml     — карта сайта для поисковиков
CNAME           — файл для GitHub Pages, говорит ему "показывай этот сайт
                  по адресу zoolavka72.ru" (без него будет работать только
                  адрес вида username.github.io)
.htaccess       — для обычного (Apache) хостинга; на GitHub Pages не нужен,
                  можно не трогать, он просто будет висеть без дела
_headers        — то же самое, для Netlify/Cloudflare Pages; на GitHub
                  Pages тоже не используется

КАК ВЫЛОЖИТЬ НА GITHUB PAGES
------------------------------
1. Зарегистрируйся на github.com (если аккаунта ещё нет) — это бесплатно.
2. Создай новый репозиторий (кнопка "New repository"), назови как хочешь,
   например zoolavka-site. Сделай его Public.
3. Загрузи в него ВСЕ файлы из этой папки (index.html, styles.css,
   script.js, images/, CNAME, robots.txt, sitemap.xml) — через кнопку
   "Add file" → "Upload files" на странице репозитория, просто перетащи
   всё содержимое папки. Файлы должны лежать в КОРНЕ репозитория, а не
   во вложенной подпапке.
4. Зайди в Settings репозитория → раздел Pages (слева в меню).
5. В "Build and deployment" → Source выбери "Deploy from a branch",
   Branch — main, папка — / (root). Сохрани.
6. Подожди 1–2 минуты — GitHub сам соберёт и опубликует сайт, даст
   временную ссылку вида https://твой-логин.github.io/zoolavka-site/.
   Открой её и проверь, что всё работает.
7. Дальше подключаем свой домен zoolavka72.ru:
   - В том же разделе Settings → Pages, в поле "Custom domain" впиши
     zoolavka72.ru и сохрани (файл CNAME в папке уже подготовлен под это).
   - Зайди в личный кабинет reg.ru → Домены → zoolavka72.ru → DNS-серверы
     / управление записями. Добавь такие записи:
       A     @     185.199.108.153
       A     @     185.199.109.153
       A     @     185.199.110.153
       A     @     185.199.111.153
       CNAME www   твой-логин.github.io.
   - DNS обновляется от нескольких минут до пары часов.
   - Когда обновится — вернись в Settings → Pages на GitHub, там появится
     галочка "Enforce HTTPS" — включи её. GitHub сам бесплатно выпустит
     SSL-сертификат для домена, ничего платить не нужно.

После этого сайт будет открываться по https://zoolavka72.ru/ с нормальным
замком в браузере, бесплатно и без хостинг-панелей.

ПОЧЕМУ ТЕПЕРЬ БЫСТРЕЕ
----------------------
Раньше все картинки были "зашиты" прямо внутрь одного html-файла — из-за
этого страница весила больше 1 МБ и браузеру приходилось грузить всё
одним куском, прежде чем показать хоть что-то. Сейчас картинки — это
обычные отдельные файлы в папке images: браузер грузит их параллельно,
кэширует (при повторном заходе скачивать заново не нужно), а те, что
ниже экрана (товары в каталоге) — подгружаются лениво, по мере
прокрутки. Сама страница (html+css+js) стала весить около 50 КБ вместо
мегабайта.

ЮРИДИЧЕСКАЯ ПЛАШКА
--------------------
В подвале сайта добавлена строка о том, что сайт не является публичной
офертой (ст. 437 ГК РФ) — это стандартная защитная формулировка для
интернет-магазинов: она означает, что цены/наличие на сайте — это
ознакомительная информация, а не официальное предложение заключить
сделку на этих условиях, и итоговые условия подтверждаются уже при
оформлении заказа. Это не заменяет полноценную юридическую консультацию,
если нужно — лучше показать сайт юристу, особенно когда пойдут первые
серьёзные объёмы продаж.

ПОЛИТИКА ОБРАБОТКИ ПЕРСОНАЛЬНЫХ ДАННЫХ И СОГЛАСИЕ КЛИЕНТА
------------------------------------------------------------
Форма заказа собирает имя, телефон, город и комментарий — по 152-ФЗ это
персональные данные, поэтому на сайте появились:
  - страница-модалка «Политика обработки персональных данных» (открывается
    по ссылке в форме заказа и в подвале сайта);
  - чекбокс согласия прямо в форме — пока клиент его не отметит, кнопка
    «Отправить заказ» не пропустит заявку.
Про куки: сейчас сайт вообще не ставит cookies (нет счётчиков и
аналитики), поэтому отдельный куки-баннер пока не нужен. Он понадобится,
если позже добавишь Яндекс.Метрику или рекламные пиксели.
Текст политики — рабочий шаблон, а не готовый юридический документ. Если
у тебя есть статус ИП/самозанятой — стоит однажды вписать туда свои
реквизиты (можно попросить меня добавить, когда решишь их оформить).

ГЕО-ТЕГИ И КЛЮЧЕВЫЕ СЛОВА
---------------------------
Добавлены:
  - расширенный список ключевых слов (meta keywords) с упоминаниями
    Тобольска и Тюменской области;
  - гео-метатеги (geo.region, geo.placename, geo.position, ICBM) —
    старый, но всё ещё местами учитываемый способ указать поисковику
    город;
  - структурированные данные (JSON-LD, тип PetStore) с адресом,
    координатами, телефоном и ссылками на ВК/Telegram — это то, что
    реально помогает Google и Яндексу понимать, что это зоомагазин
    именно в Тобольске, и может подтянуться в локальную выдачу/карты.

Дополнительно советую (руками, вне этого пакета):
  - Зарегистрировать сайт в Яндекс.Вебмастере и Google Search Console,
    отправить туда sitemap.xml — тогда поисковики узнают о сайте
    быстрее;
  - Завести карточку в Яндекс Картах / 2ГИС на реальный адрес (если
    есть точка самовывоза) — это отдельная история, сайт тут не
    помощник.

ВАЖНО ЗНАТЬ ПРО TELEGRAM-БОТА ЗАКАЗОВ
----------------------------------------
Токен бота для приёма заказов "зашит" прямо в script.js — это
единственный способ отправлять заказы без своего сервера. Он виден
любому, кто откроет исходный код страницы. Практический риск небольшой
(твои переписки в Telegram никто прочитать не сможет), но теоретически
кто-то мог бы прислать через него "мусорные" заявки в твой чат с ботом.
Если начнёт бесить спам — просто создай нового бота через @BotFather и
пришли мне новый токен, я обновлю сайт.
